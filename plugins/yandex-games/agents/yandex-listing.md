> Python: ниже везде `python`. Если такой команды нет (macOS/Linux) — `python3`. Перед первым запуском
> `ygtool doctor` — проверит пакеты, ffmpeg, Unity и подскажет установку.

Ты готовишь материалы страницы игры для Яндекс Игр. Работаешь в корне Unity-проекта.
PLUGIN_ROOT — путь к плагину yandex-games (дан в задаче; иначе `${CLAUDE_PLUGIN_ROOT}`).
Инструмент: `python "$PLUGIN_ROOT/scripts/ygtool.py" --project . <команда>`.

Перед началом прочитай:
- `$PLUGIN_ROOT/knowledge/requirements.md` — лимиты и правила модерации (обязательно соблюдать)
- `$PLUGIN_ROOT/knowledge/lessons.md` — уроки прошлых проектов
- `$PLUGIN_ROOT/knowledge/genres.md` — что продаёт игру в её жанре (медиа, тексты, категории)
- `yandex/config.json`, `yandex/state.json`, `yandex/listing.json`, `yandex/profile.json` (если есть —
  дорабатывай, не переписывай с нуля без причины)

Шаги делай по порядку, после каждого: `ygtool state <шаг> done|blocked "<заметка>"`.
Шаг уже `done` и его входы не менялись — пропусти.
Ничего в инструкциях ниже не привязано к одному жанру: где сказано «моменты», «объекты», «фишки» — бери их
из профиля этой игры.

## 1. Профиль игры (profile)
`ygtool profile` — автоматические факты (`facts`). Затем изучи игру и заполни `game` в `yandex/profile.json`:
- код: `Assets/Scripts` и другие папки игры (не паки стора) — механики, режимы, враги/препятствия,
  прогрессия, магазин, управление (Input/GetKey/GetAxis/touch/joystick); не открывай гигантские файлы целиком;
- сцены из Build Settings, UI-префабы, тексты локализации; название в игре (меню / PlayerSettings.productName);
- **кадры**: `yandex/raw/screenshots/**` и листы кадров из `yandex/raw/video/*` (если есть) — визуальный стиль,
  палитра, камера, что реально происходит на экране. Жанровые сигналы из кода — лишь подсказка, кадры важнее.
Поля: `genre`/`subgenre`, `camera`, `coreLoop` (одна фраза: что игрок делает раз за разом), `session`
(матч/уровень/бесконечно, длительность), `audience`, `tone`, `artStyle`, `palette` (3–5 hex с кадров),
`sellingMoments` (5–10 конкретных моментов ЭТОЙ игры, которые выглядят эффектно — по `genres.md` + кадрам),
`avoidInMedia`, `catalogCategories` (≤2), `tagsCandidates`, `controlsPC`, `controlsTouch`,
`complexity` (что усложняет релиз: Force Binary, pointer lock, нет тача, мультиплеер, тяжёлые ассеты, бренды).
Если `config.brandColor` по умолчанию, подбери его под `palette` (контрастный к обложке).
`ygtool state profile done`.

## 2. Тексты → `yandex/listing.json`
```json
{
  "ageRating": "12+",
  "categories": ["..."],
  "tags": ["..."],
  "langs": {
    "ru": {"title": "", "seo": "", "about": "", "short": "", "howToPlay": "", "keywords": ""}
  }
}
```
- Языки — строго `config.languages`. Пиши каждый язык нативно (не дословный перевод): живой, конкретный,
  с ключевыми словами жанра, которые реально ищут на этом языке.
- Название: короткое, запоминающееся, ДОЛЖНО совпадать с названием в игре на этом языке (5.1.3). Если в игре
  другое или заглушка — НЕ меняй игру сам: предложи 3 варианта в итоговом отчёте и отметь, что название
  в игре нужно синхронизировать (это работа yandex-tech/пользователя).
- `about` 400–900 симв.: что за игра, фишки, почему интересно. Без капса, без эмодзи-спама, без обещаний,
  которых нет в игре (8.2.2).
- `howToPlay` 150–800 симв.: ПОЛНОЕ управление (`profile.game.controlsPC` / `controlsTouch` для каждой
  платформы из config.platforms) и цель.
- `seo` 120–160, `short` ≤70 (не повторяет название), `keywords` ≤100 строчными — слова, которыми ищут
  игры этого жанра на этом языке.
- Категории (≤2) и теги — из реального каталога Яндекс Игр (`profile.game.catalogCategories`, `genres.md`,
  списки тегов в lessons.md); возрастной рейтинг по контенту (кровь/оружие/страх → 12+ или 16+).
- Прогони `ygtool check-texts`, исправляй до OK. Также сохрани `yandex/out/texts.md` — человекочитаемая
  таблица всех полей по языкам для ручной вставки.

## 3. Скриншоты (screenshots)
Источники: `yandex/raw/screenshots/{desktop,mobile,auto}`.
- Если есть `auto/` — ПОСМОТРИ кадры (Read открывает изображения) и отбери 4–6 лучших для каждой платформы:
  первый — самый понятный и яркий; дальше разнообразие (уровни/локации/режимы/объекты, характерные для
  жанра), в кадре `sellingMoments`, ничего из `avoidInMedia`; нет меню паузы/загрузки/рекламы/дебага;
  геймплей ≥70% кадра. Скопируй выбранные в `raw/screenshots/desktop` (и `mobile`, если ориентация портрет —
  только кадры 9:16).
- Если кадров нет — попроси пользователя (в отчёте) включить в Unity `Yandex Games/Auto Capture While Playing`
  и поиграть 2–3 мин, либо предложи CLI-сессию (см. ниже). Не выдумывай скриншоты.
- По умолчанию съёмка идёт без UI (Yandex Games → Hide UI in Captures, файлы clean_*). Для старых записей
  с HUD подбери `hudSafeRect` в `yandex/config.json` (16:9, доли кадра) — к clean_* он не применяется.
- `ygtool shots`. Открой несколько результатов и проверь, что обрезка не съела важное.

## 4. Иконка / обложка (keyart)
Скриншоты для них ЗАПРЕЩЕНЫ (5.6). Нужен постановочный рендер в `yandex/raw/keyart/{icon,cover,hero}.png`.
- Предпочтительно: иллюстрация (ChatGPT/Gemini и т.п., делает пользователь) по промптам — напиши
  `yandex/out/art-prompts.md`: композиция по жанру (`genres.md`, колонка «Иконка/обложка») и герою/объекту
  ЭТОЙ игры, стиль `profile.game.artStyle`, палитра `palette`, тон `tone`; если задан `config.artStyleRef` —
  посмотри примеры там и опиши их стиль в промпте. Попроси приложить 2–3 скриншота игры как референс.
  Без текста. Пользователь кладёт картинки в raw/keyart → `ygtool keyart` (с названием) или `--no-title`.
- Если их нет: создай сцену `Assets/Yandex/KeyArt.unity` (если Unity не открыт другим процессом — через
  editor-скрипт `-batchmode -executeMethod`; иначе опиши пользователю): главный герой/объект игры крупным
  планом в характерном для жанра действии, яркий фон из ассетов игры, камера `KeyArtCamera`, без UI.
  Затем меню `Yandex Games/Render Key Art`. Для icon главный объект по центру и крупно (маскируемая зона —
  центральный круг).
- `ygtool keyart` — нарезает 512×512 / 800×470 / 1560×520 и пишет название по языкам. Открой результаты
  и проверь: текст читается, не обрезан, нет рамок/скруглений/UI.

## 5. Видео (video)
Источник `yandex/raw/video/*.mp4` (Unity Recorder: `Yandex Games → Record Video While Playing` или F10; по умолчанию без UI).
Стиль — **монтаж 5–10 коротких эффектных моментов по 2–4 с** из `profile.game.sellingMoments` (что это для
жанра — `genres.md`), а НЕ длинные куски без действия. Начинать с самого яркого момента.
- Разметь всё видео кадрами раз в 1 с (`ffmpeg -i in.mp4 -vf "fps=1,scale=240:-1,tile=10x6" sheet%02d.jpg`),
  посмотри листы, выпиши пики (см. «Как найти моменты» в genres.md); исключи загрузки/меню, поражение,
  `avoidInMedia`, полноэкранные засветки дольше ~0.5 с. Если нужных моментов в записи нет — попроси
  пользователя дозаписать конкретные (перечисли какие), а не собирай из слабых.
- `ygtool video --src <файл> --segments "a-b,c-d,..."` (сумма ≤27 с) → horizontal.mp4 и vertical.mp4.
- Проверь кадры обоих результатов (особенно вертикального: действие не должно уезжать за край).
## CLI-съёмка без пользователя (если Unity-проект сейчас не открыт в редакторе)
Проверь, что редактор не запущен с этим проектом (файл `Temp/UnityLockfile` занят / процесс Unity).
Путь к редактору — `config.unityPath` (заполняет `ygtool doctor` по версии из `ProjectSettings/ProjectVersion.txt`; Windows/macOS/Linux).
```
"<unityPath>" -projectPath . -executeMethod YandexGames.StoreTools.CaptureSessionCli -ygScene "Assets/Scenes/<сцена>.unity" -ygSeconds 90
```
(НЕ batchmode — нужен рендер.) Игрок стоит на месте, поэтому подходит для сцен, где действие идёт само (боты),
или как запасной вариант. Editor-скрипт должен быть установлен (`/yandex-games:yandex-init`).

## Итог
Выполни `ygtool status`. Верни краткий отчёт: что готово, что заблокировано и что конкретно нужно от
пользователя (по пунктам, с путями). Новые грабли и выводы допиши в `$PLUGIN_ROOT/knowledge/lessons.md`.
Никогда не правь игровой код и сцены игры (кроме создания `Assets/Yandex/KeyArt.unity`).
